# 第 5 階段：重建輸出並做英文基準測試

目標清單有幾個資料夾是工具「產生」的，無法下載，要在你的電腦上重建。這一階段依固定順序跑完這些工具，開新遊戲測試，然後把英文版凍結備份成「EN-baseline」。

- 預估時間：一整天（草地快取 0.5–2.5 小時，DynDOLOD 數小時）。
- 前提：第 4 階段的退出條件都已達成。
- 全程**插電**，筆電放在通風處。這些工具會長時間滿載。

## 輸出對照表

輸出一律放進目標清單中**已經存在的同名佔位資料夾**（`D:\PM\mods\` 底下）：

| 順序 | 工具 | 輸出資料夾 | 會產生的插件 |
|---|---|---|---|
| 1 | Pandora | `Pandora Output` | 視需要產生 `FNIS.esp` |
| 2 | BodySlide | `BodySlide (Nude)` | 無 |
| 3 | Synthesis | `SYNTHESSIS` | `Synthesis.esp` |
| 4 | PGPatcher | `pgpatcher_output` | `PGPatcher.esp`，必要時 `PG_1.esp`、`PG_2.esp` |
| 5 | NGIO 草地快取 | `grass CS` | 無（`.cgid` 檔） |
| 6 | xLODGen（地形） | `lodgen2` | 無 |
| 7 | TexGen | `texgenCS` | 無 |
| 8 | DynDOLOD | `dyndolodCS2` | `DynDOLOD.esm`、`DynDOLOD.esp`、`Occlusion.esp` |

`overwrite2` 是原作者的私人資料夾，無法重建，保持空的即可。

## 共通原則

- **一律從 MO2 啟動工具**（右上方執行檔下拉選單）。`build_instance.py` 已把找到的工具加進清單（SSEEdit、DynDOLOD、TexGen、xLODGen、PGPatcher、BodySlide、Pandora 等）。
- 修改執行檔的引數：下拉選單最後一項「<Edit…>」→ 選工具 → 修改「Arguments」→ 確定。
- 清單中沒有某個工具時，在「<Edit…>」按「+」→「Add from file…」，選該工具的 `.exe` 自行加入。
- 工具結束後，看 MO2 左側最下方的 **Overwrite**。如果裡面有新檔案，就用它上面的右鍵選單「Move content to Mod…」移到對應的輸出資料夾。
- 要改某個 mod 的設定檔時，不要直接改原檔（可能是硬連結）。做法：
  1. 在 MO2 建立一個空的 mod：左側清單按右鍵 →「Create empty mod」，命名 `Pages - 設定覆寫`，放在清單最下方附近並啟用。
  2. 把要改的檔案依相同路徑複製進 `D:\PM\mods\Pages - 設定覆寫\`，再改那份。
- 每個工具跑完、搬好輸出後，按 `F5` 重新整理 MO2，確認輸出資料夾已啟用。
- **工具設定檔的硬連結**：BodySlide、DynDOLOD、xEdit 等會改寫自己資料夾裡的設定檔與記錄檔（`Config.xml`、`*.ini`、`*.log`）。這些檔多半是從 Nolvus／M&V 擷取的硬連結，直接改寫會連帶改到來源實例。每個工具**第一次執行前**（工具先關閉）執行：
  ```bat
  python tools\unshare_links.py --path "D:\PM\mods\BodySlide and Outfit Studio\CalienteTools\BodySlide" --apply
  python tools\unshare_links.py --path D:\PM\tools --apply
  ```
  它只把設定類檔案換成內容相同的獨立副本，來源實例的檔案不變，也不會刪除任何資料。
- **被其他 mod 蓋掉的設定檔**：`unshare_links` 只處理工具自己資料夾裡的檔案。如果另一個優先順序更高的 mod 帶了同名設定檔（例如 M&V 的 Settings Hub 帶了 BodySlide 的 `Config.xml`），MO2 實際給工具的是那一份，而它也是硬連結。這種檔一律複製到 `Pages - 設定覆寫` 的相同路徑再修改（`Pages - 設定覆寫` 在 modlist 最上方）。
- **完整插件名額**：第 4 階段結束時是 252／254。`DynDOLOD.esm`、`DynDOLOD.esp` 一定是完整插件，會用掉最後 2 個名額。所以其他輸出（`Synthesis.esp`、`FNIS.esp`、`Occlusion.esp`、`PG_*.esp`）**都必須是輕量插件**。
  - 每個工具的輸出搬好後，關 MO2 跑 `sync-order --apply` 和 `check_plugins`，看「完整插件數」與「輸出重建後的完整插件（預估）」。MO2 會把新出現的輸出插件列成停用；`sync-order` 會自動改回啟用（報告的「啟用重建出來的輸出插件」）。
  - 輸出插件如果是完整插件，用 `esl_check` 加 ESL 旗標（先試跑，再加 `--apply`；它只會改重建出來的檔案，不會改硬連結的原檔）：
    ```bat
    python tools\esl_check.py --plugin "D:\PM\mods\SYNTHESSIS\Synthesis.esp" --flag
    python tools\esl_check.py --plugin "D:\PM\mods\SYNTHESSIS\Synthesis.esp" --flag --apply
    ```
  - 加不上旗標，或預估超過 254 時，停下來回報 Claude。

## 1. Pandora（行為檔）

Pandora 4.3.1-beta **不採用 `-o` 引數**，它讀寫的是自己設定檔裡的路徑。沒改的話會讀寫 Steam 的遊戲資料夾。

1. 關閉 Pandora，備份 `%LOCALAPPDATA%\Pandora Behaviour Engine\Settings.json`（另存成 `Settings.json.bak-日期`），再用記事本修改這兩項：
   ```json
   "gameDataPath": "D:\\PM\\STOCK GAME\\Data",
   "outputPath": "D:\\PM\\mods\\Pandora Output"
   ```
2. MO2「<Edit…>」清單沒有 Pandora 時，按「+」→「Add from file…」，選 `D:\PM\mods\Pandora Behaviour Engine v4.3.1-beta\` 裡的 Pandora 執行檔。
   - 「Start in」（工作目錄）設為 `D:\PM\STOCK GAME\Data`。
3. 從 MO2 執行 Pandora，patch 清單保持預設，按開始執行的按鈕，等它完成。
4. 確認：
   - 輸出在 `D:\PM\mods\Pandora Output`（`meshes`、`Pandora_Engine`、`SKSE`、`Engine.log`）。
   - Steam 遊戲資料夾的 `Data` 沒有新檔案。
5. `FNIS.esp` 是 Pandora 資料夾附的空插件，它是完整插件。用 `esl_check --flag` 加 ESL 旗標（見「共通原則」的完整插件名額）。

## 2. BodySlide（服裝體型）

目標的身體組合來自 Nolvus：女性 CBBE 3BA（3BBB）、男性 HIMBO＋The New Gentleman。做法照 Nolvus 手冊（10.3 Body Slide），使用者選了裸體版。

1. 關閉 MO2，先把 BodySlide 設定檔的硬連結換成獨立副本（見「共通原則」）：
   ```bat
   python tools\unshare_links.py --path "D:\PM\mods\BodySlide and Outfit Studio\CalienteTools\BodySlide" --apply
   ```
2. **設定檔覆寫**：M&V 的 `Mages & Vikings - Settings Hub` 自帶一份 `CalienteTools\BodySlide\Config.xml`，優先順序比 BodySlide 高。它的路徑指向 M&V 的電腦，而且是 D:\MV 的硬連結。
   1. 把 BodySlide 自己資料夾裡的 `Config.xml` 複製到 `D:\PM\mods\Pages - 設定覆寫\CalienteTools\BodySlide\Config.xml`。`Pages - 設定覆寫` 放在 modlist 最上方（最高優先）。
   2. 在那份副本中設定：
      - `GameDataPath`：`D:\PM\STOCK GAME\Data\`
      - `OutputDataPath`：`D:\PM\mods\BodySlide (Nude)\`
   3. 不要在 BodySlide 的 Settings 按 OK：按了會寫到 Settings Hub 那份。
3. 從 MO2 執行 BodySlide，確認沒有「No read/write permission」的警告。
4. 主畫面：
   - Outfit/Body：`CBBE 3BBB Body Amazing`
   - Preset：`CBBE Curvy (Outfit)`（選好後滑桿會移動）
   - **勾選**「Build Morphs」：Nolvus 的輸出有 `.tri` 檔，身體檔也有 BODYTRI，表示它有建 morphs。
5. 按「Batch Build...」，**勾選狀態不要動**，直接按「Build」。
   - `BuildSelection.xml` 會先取消各組落選的候選。如果改成全選，就會跳出「Choose output set」視窗。
6. 衝突的選擇已經存在 BodySlide 資料夾的 `BuildSelection.xml`，所以不會跳出「Choose output set」；逐組的選擇與理由在 `data/analysis/bodyslide_choices.csv`。
   - 原則：Nolvus 有做的組照 Nolvus 的實際選擇（例如手用 Female Hands Redone、男性身體用 `HIMBO Body - SOS High Poly Phys CBPC`）。其他組依序選 3BA／3BBB → CBBE Physics／SMP → CBBE → Frankly HD，不選 BHUNP、UBE、TBBP。
   - 如果仍跳出選擇視窗（例如新加了服裝）：照上面的原則選，判斷不了的保留預設，記下組名回報 Claude。
7. 等它完成，然後檢查：
   - `CalienteTools\BodySlide\Log_BS.txt` 有「Applying preset 'CBBE Curvy (Outfit)'」、「TRI = True」與「All sets processed successfully!」。
   - 沒有「TRI = True」表示漏勾 Build Morphs。可以先關 BodySlide，把 BodySlide 資料夾裡 `BodySlide.xml` 的 `BuildMorphs` 改成 `true`（先備份），再重開建置。
   - `BodySlide (Nude)` 有 nif 和 tri 檔；Overwrite 沒有 `meshes`（有的話用「Move content to Mod…」移過去）。
8. 回報：`BodySlide (Nude)` 的 nif／tri 數量。

## 3. Synthesis

Nolvus v6 內建的 Synthesis.esp 只覆寫地形（LAND／CELL／WRLD）。它用的 patcher 是 **Skyrim-RemoveLandscapeVertexColor**（作者 Jampi0n，`https://github.com/Jampi0n/Skyrim-RemoveLandscapeVertexColor`）的**預設設定**。
- 名稱雖然叫 Remove，但預設不是移除頂點顏色，而是用公式把它調亮：一般地形 `Pow(x/255,0.5)*255`，雪地 `Pow(x/255,0.1)*255`。
- Nolvus 那份的 LAND 全都有 VCLR，平均亮度從原版的 239 變成 249，和這個公式吻合。
- 我們只用這一個 patcher（Nolvus v6 已不用 Water Does Damage）。

1. （唯讀）先看 Nolvus 那份的 LAND：
   ```bat
   python tools\esl_check.py --plugin "D:\Nolvus\Instances\Nolvus Awakening\MODS\mods\Synthesis Patch - NOSREX\Synthesis.esp" --subrecords LAND
   ```
   預期：LAND 7,664 筆，VCLR 也是 7,664 筆（每一筆都有）。
2. 從 GitHub 的 Mutagen-Modding／Synthesis 發行頁下載最新版，解壓縮到 `D:\PM\tools\Synthesis`。
   - 先安裝 **.NET 10 SDK**（Microsoft 官網；要先問使用者）。Synthesis 0.36 以後會把 patcher 改用 net10.0 編譯，沒有 SDK 就會出現 Compilation Error。
3. 在 MO2「<Edit…>」按「+」→「Add from file…」，選 `Synthesis.exe`，標題填 `Synthesis`。
4. 從 MO2 執行。在 Synthesis 的設定（齒輪）→ Profile，把 Data Folder 手動設為 `D:\PM\STOCK GAME\Data`，否則 mod 都會顯示 Missing。
   - patcher 第一次編譯可以在 MO2 外開 Synthesis 做；**產生 Synthesis.esp 一定要從 MO2 執行**（這樣才看得到所有 mod）。
5. 加入 patcher：
   1. 按「Add」→ Git Repository，Repository Path 填 `https://github.com/Jampi0n/Skyrim-RemoveLandscapeVertexColor`，Project 選 `RemoveLandscapeVertexColor\RemoveLandscapeVertexColor.csproj`。在 patcher 瀏覽清單搜尋 `Vertex` 也可以。
   2. 等它編譯完成，顯示 Ready。
   3. **Settings 保持預設**：`removeAllVertexVertexColors` 不要勾，`advanced` 的公式不要改。
   4. 只加這一個，按執行。
6. 完成後，`Synthesis.esp` 會出現在 Overwrite，用「Move content to Mod…」移到 `SYNTHESSIS`。
7. 關 MO2，檢查並加上 ESL 旗標（它只有覆寫，應該可以直接加）：
   ```bat
   python tools\esl_check.py --plugin "D:\PM\mods\SYNTHESSIS\Synthesis.esp" --subrecords LAND --flag
   python tools\esl_check.py --plugin "D:\PM\mods\SYNTHESSIS\Synthesis.esp" --flag --apply
   ```
   - 第一行：LAND 的每一筆都應該有 VCLR。如果 VCLR 是 0，表示勾到了「移除全部」，要改回預設後重跑。
   - 回報 LAND 筆數和前置數量，和 Nolvus 那份（7,664 筆、55 個前置）比較。我們的清單不同，數字不會完全一樣。

## 4. PGPatcher（視差與 PBR 網格）

1. 確認 `dyndolodCS2`、`texgenCS`、`pgpatcher_output` 目前都是空的（第一次做一定是空的）。
2. PGPatcher 資料夾的 `cfg\settings.json` 是 M&V 的設定，裡面的 `D:\MV` 路徑要改成 `D:\PM`（先備份）。
3. 在 MO2 **暫時停用 `pgpatcher_output`**（輸出 mod 啟用時 PGPatcher 會出現 Critical Error）。
4. 從 MO2 執行 PGPatcher，在「Output → Location」設為 `D:\PM\mods\pgpatcher_output`。
5. 其餘用預設值（Claude 另有指示則照做），按開始，等它完成。
6. 重新啟用 `pgpatcher_output`。產生的 `PGPatcher.esp`、`PG_1.esp` 應該都是輕量插件；PG 插件的數量依記錄數而定，只有 `PG_1.esp` 是正常的。

## 5. NGIO 草地快取

目標用 Freak's Floral Fields（FFF），它是依 `iMinGrassSize=60` 製作的。

### 5.1 選擇遠景草地方案

| 方案 | 內容 | 適合 |
|---|---|---|
| **A（建議）** | 使用 CS 的 Grass Optimizations；DynDOLOD 不產生草 LOD；NGIO 開啟「延伸草地距離」 | 筆電，較省效能 |
| B | 不用 Grass Optimizations；DynDOLOD 產生草 LOD（密度 50% 以下） | 想要傳統做法 |

不確定就選 A。第 4 階段應已安裝 Grass Optimizations。

### 5.2 設定 GrassControl.ini

1. 找到 NGIO 的設定檔 `GrassControl.ini`：先看 MO2 的 Overwrite（第一次啟動遊戲時會自動產生在那裡），沒有的話看 `NGIO - NG (1.5.11)` 資料夾的 `SKSE\Plugins\`。
2. 複製到 `D:\PM\mods\Pages - 設定覆寫\SKSE\Plugins\GrassControl.ini`。如果原本在 Overwrite，就把 Overwrite 裡那份刪掉。
3. 用記事本修改這幾行：
   ```ini
   Use-grass-cache = true
   Only-load-from-cache = true
   Overwrite-min-grass-size = 60
   ```
   方案 A 另外設定：
   ```ini
   Extend-grass-distance = true
   DynDOLOD-Grass-Mode = 0
   ```

### 5.3 產生快取

1. 在 MO2 **暫時停用 `True HUD`**（NGIO 說明指出它會在產生快取時造成當機）。
2. 啟動方式二選一：
   - 如果 MO2 上方拼圖圖示的選單中有「Precache Grass」，按它。當機時 MO2 會自動重開遊戲，直到完成。
   - 否則在 `D:\PM\STOCK GAME\` 建立一個空的文字檔 `PrecacheGrass.txt`，再用 SKSE 啟動遊戲。每次當機就重新啟動，直到完成。
3. 完成時會跳出「Grass generation finished successfully!」，NGIO 的記錄檔（`SKSE` 資料夾的 `NGIO-NG.log`）也會有這一行。**用這一行判斷完成**。
   - `PrecacheGrass.txt` 會被 Root Builder 重導到 `D:\PM\overwrite\Root`，所以不要用「`STOCK GAME` 裡的 `PrecacheGrass.txt` 不見了」來判斷。完成後把它搬到 `_replaced`。
4. 快取檔（`.cgid`）會在 Overwrite 的 `grass` 資料夾裡，用「Move content to Mod…」移到 `grass CS`。檔案要保留在 `grass` 子資料夾中。
5. 看看有沒有 `.fail` 檔。有的話表示那些區域會沒有草，回報 Claude。
6. 重新啟用 `True HUD`。

## 6. xLODGen（地形 LOD）

1. 在「<Edit…>」中選 xLODGen，引數填：
   ```
   -SSE -D:"D:\PM\STOCK GAME\Data" -o:"D:\PM\gen\lodgen"
   ```
   `-o:` 要指到 VFS 以外的空資料夾。
2. 從 MO2 執行，全選世界空間。
3. **取消預設勾選的 Objects LOD 和 Trees LOD，只勾 Terrain LOD**（地形）。其餘參數用預設值。
4. 完成後（最後一行是「LOD generation done.」），把 `D:\PM\gen\lodgen` 裡的**全部內容**移到 `D:\PM\mods\lodgen2`。

## 7. TexGen

1. 在「<Edit…>」中選 TexGen，引數填 `-SSE -D:"D:\PM\STOCK GAME\Data"`。
2. 從 MO2 執行。畫面上的輸出路徑如果是 `D:\MV\...`，改成 `D:\PM\tools\DynDOLOD\TexGen_Output\`（預設設定檔來自 M&V）。
3. 其餘用預設設定按「Start」。方案 A 不勾 Grass、HD Grass。
   - 載入插件時如果跳出「Record … is being overridden by …」錯誤，先停下回報 Claude（這表示有補丁和主插件版本不符）。
4. 完成後按「Exit TexGen」（不是 Zip and Exit），把 `TexGen_Output` 的全部內容移到 `D:\PM\mods\texgenCS`。
4. 按 `F5` 重新整理，確認 `texgenCS` 已啟用。

## 8. DynDOLOD

1. DynDOLOD 資料夾的預設設定檔來自 M&V：`Edit Scripts\DynDOLOD\` 與 `Presets\` 裡的 `.ini`（例如 `DynDOLOD_SSE_Default.ini`）有 `OutputPath=D:\MV\…` 和 LODGen 規則路徑。先把這些設定檔裡的 `D:\MV` 全部改成 `D:\PM`（先備份；記錄檔不用改）。刪除 D:\MV 之前一定要做完。
2. 在「<Edit…>」中選 DynDOLOD，引數填 `-SSE -D:"D:\PM\STOCK GAME\Data"`。
3. 從 MO2 執行，選 **High** 預設（M&V 的設定檔是 Low，要改）。
   - 輸出路徑：`D:\PM\tools\DynDOLOD\DynDOLOD_Output\`。
   - 方案 A：與草（Grass）相關的 LOD 選項不要勾選。
   - 勾選 Occlusion（目標有 `Occlusion.esp`）。
   - 不確定時先截圖給 Claude。
4. 按開始。這會跑好幾個小時。
5. 如果中途停下來並顯示錯誤，把 DynDOLOD 資料夾中 `Logs` 裡最新的記錄檔上傳。
6. 完成後，把 `DynDOLOD_Output` 的全部內容移到 `D:\PM\mods\dyndolodCS2`。
   - 應該有 `DynDOLOD.esm`、`DynDOLOD.esp`（完整插件）與 `Occlusion.esp`（DynDOLOD 會盡量加 ESL 旗標；如果是完整插件，用 `esl_check --flag` 處理）。

## 9. 還原插件順序並檢查

關閉 MO2，執行：

```bat
cd /d C:\PagesTools
python tools\build_instance.py sync-order --pm D:\PM
python tools\build_instance.py sync-order --pm D:\PM --apply
python tools\check_plugins.py --pm D:\PM
python tools\audit_skse.py --pm D:\PM
```

- `sync-order` 第一行是試跑，第二行才寫入。它會把新產生的輸出插件放回目標位置：`DynDOLOD.esm` 在其他 ESM 之後，`DynDOLOD.esp`、`Occlusion.esp` 等放在最後。
- `check_plugins` 這時「待重建的輸出插件」應為 0，而且沒有 `[失敗]`。

## 10. 第一次用 Community Shaders 啟動

1. 從 MO2 用 SKSE 啟動。
2. 左上角出現「Compiling Shaders」時，等它跑完（第一次可能很久）。之後啟動就會很快。
3. 按 `End` 可以開啟 CS 選單。這一階段先用預設值，第 7 階段再調整。

## 11. 新遊戲測試

照 [測試路線](測試路線.md) 開**新遊戲**，走完 30–60 分鐘的固定路線，並記錄結果。

## 12. 凍結為 EN-baseline

測試通過後：

## 常見問題

**Overwrite 裡出現其他工具的零碎檔案？**
截圖回報 Claude，不要隨便刪。多數是設定檔，可以移到 `Pages - 設定覆寫`。

**草地快取一直重新開始、停不下來？**
NGIO 說明提到 Root Builder 可能造成這個問題（MO2 plugins 資料夾可能有 M&V 帶來的 Root Builder）。回報 Claude。

**DynDOLOD 說缺少前置或插件有錯誤？**
先執行 `check_plugins.py`，再把兩邊的報告一起上傳。

**遊戲裡有紫色材質或紅色驚嘆號？**
紫色是缺材質檔，紅色驚嘆號是缺模型檔。截圖並記下位置，回報 Claude。
