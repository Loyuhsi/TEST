# 第 5 階段：重建輸出並做英文基準測試

目標清單有幾個資料夾是工具「產生」的，無法下載，要在你的電腦上重建。這一階段依固定順序跑完這些工具，開新遊戲測試，然後把英文版凍結備份成「EN-baseline」。

- 預估時間：一整天（草地快取 0.5–2.5 小時，DynDOLOD 數小時）。
- 前提：第 4 階段的退出條件都已達成。
- 全程**插電**，筆電放在通風處。這些工具會長時間滿載。

## 輸出對照表

輸出一律放進目標清單中**已經存在的同名佔位資料夾**（`D:\PM\mods\` 底下）：

| 順序 | 工具 | 輸出資料夾 | 會產生的插件 |
|---|---|---|---|
| 1 | Pandora | `Pandora Output` | 視需要產生 `FNIS.esp` |
| 2 | BodySlide | `BodySlide (Dressed)` | 無 |
| 3 | Synthesis | `SYNTHESSIS` | `Synthesis.esp` |
| 4 | PGPatcher | `pgpatcher_output` | `PGPatcher.esp`，必要時 `PG_1.esp`、`PG_2.esp` |
| 5 | NGIO 草地快取 | `grass CS` | 無（`.cgid` 檔） |
| 6 | xLODGen（地形） | `lodgen2` | 無 |
| 7 | TexGen | `texgenCS` | 無 |
| 8 | DynDOLOD | `dyndolodCS2` | `DynDOLOD.esm`、`DynDOLOD.esp`、`Occlusion.esp` |

`overwrite2` 是原作者的私人資料夾，無法重建，保持空的即可。

## 共通原則

- **一律從 MO2 啟動工具**（右上方執行檔下拉選單）。`build_instance.py` 已把找到的工具加進清單（SSEEdit、DynDOLOD、TexGen、xLODGen、PGPatcher、BodySlide、Pandora 等）。
- 修改執行檔的引數：下拉選單最後一項「<Edit…>」→ 選工具 → 修改「Arguments」→ 確定。
- 清單中沒有某個工具時，在「<Edit…>」按「+」→「Add from file…」，選該工具的 `.exe` 自行加入。
- 工具結束後，看 MO2 左側最下方的 **Overwrite**。如果裡面有新檔案，就用它上面的右鍵選單「Move content to Mod…」移到對應的輸出資料夾。
- 要改某個 mod 的設定檔時，不要直接改原檔（可能是硬連結）。做法：
  1. 在 MO2 建立一個空的 mod：左側清單按右鍵 →「Create empty mod」，命名 `Pages - 設定覆寫`，放在清單最下方附近並啟用。
  2. 把要改的檔案依相同路徑複製進 `D:\PM\mods\Pages - 設定覆寫\`，再改那份。
- 每個工具跑完、搬好輸出後，按 `F5` 重新整理 MO2，確認輸出資料夾已啟用。

## 1. Pandora（行為檔）

1. 在「<Edit…>」中選 Pandora，引數填：
   ```
   -o "D:\PM\mods\Pandora Output"
   ```
2. 從 MO2 執行 Pandora，patch 清單保持預設，按開始執行的按鈕，等它完成。
3. 輸出直接寫進 `Pandora Output`。不要使用 MO2 的「Create files in mod」選項。

## 2. BodySlide（服裝體型）

1. 從 MO2 執行 BodySlide。
2. 按下方的「Settings」，把輸出路徑（Output Path）設為 `D:\PM\mods\BodySlide (Dressed)`。
3. 選擇 Preset，以及是否勾選「Build Morphs」：**照 Claude 看過第 3 階段盤點後給你的指示**。
4. 按「Batch Build」，全部勾選，按「Build」，等它完成。

## 3. Synthesis

1. 從 GitHub 的 Mutagen-Modding／Synthesis 發行頁下載最新版，解壓縮到 `D:\PM\tools\Synthesis`。
2. 在 MO2「<Edit…>」按「+」→「Add from file…」，選 `Synthesis.exe`，標題填 `Synthesis`。
3. 從 MO2 執行。如果它要求安裝 .NET SDK，照提示安裝。
4. 要加入哪些 patcher，**Claude 會在看過第 3 階段的盤點後給你清單**。照清單加入後按執行。
5. 完成後，`Synthesis.esp` 會出現在 Overwrite，用「Move content to Mod…」移到 `SYNTHESSIS`。

## 4. PGPatcher（視差與 PBR 網格）

1. 確認 `dyndolodCS2`、`texgenCS`、`pgpatcher_output` 目前都是空的（第一次做一定是空的）。
2. 從 MO2 執行 PGPatcher。
3. 在「Output → Location」設為 `D:\PM\mods\pgpatcher_output`。
4. 其餘用預設值（Claude 另有指示則照做），按開始，等它完成。

## 5. NGIO 草地快取

目標用 Freak's Floral Fields（FFF），它是依 `iMinGrassSize=60` 製作的。

### 5.1 選擇遠景草地方案

| 方案 | 內容 | 適合 |
|---|---|---|
| **A（建議）** | 使用 CS 的 Grass Optimizations；DynDOLOD 不產生草 LOD；NGIO 開啟「延伸草地距離」 | 筆電，較省效能 |
| B | 不用 Grass Optimizations；DynDOLOD 產生草 LOD（密度 50% 以下） | 想要傳統做法 |

不確定就選 A。第 4 階段應已安裝 Grass Optimizations。

### 5.2 設定 GrassControl.ini

1. 找到 NGIO 的設定檔 `GrassControl.ini`：先看 MO2 的 Overwrite（第一次啟動遊戲時會自動產生在那裡），沒有的話看 `NGIO - NG (1.5.11)` 資料夾的 `SKSE\Plugins\`。
2. 複製到 `D:\PM\mods\Pages - 設定覆寫\SKSE\Plugins\GrassControl.ini`。如果原本在 Overwrite，就把 Overwrite 裡那份刪掉。
3. 用記事本修改這幾行：
   ```ini
   Use-grass-cache = true
   Only-load-from-cache = true
   Overwrite-min-grass-size = 60
   ```
   方案 A 另外設定：
   ```ini
   Extend-grass-distance = true
   DynDOLOD-Grass-Mode = 0
   ```

### 5.3 產生快取

1. 在 MO2 **暫時停用 `True HUD`**（NGIO 說明指出它會在產生快取時造成當機）。
2. 啟動方式二選一：
   - 如果 MO2 上方拼圖圖示的選單中有「Precache Grass」，按它。當機時 MO2 會自動重開遊戲，直到完成。
   - 否則在 `D:\PM\STOCK GAME\` 建立一個空的文字檔 `PrecacheGrass.txt`，再用 SKSE 啟動遊戲。每次當機就重新啟動，直到完成。
3. 完成時會跳出「Grass generation finished successfully!」。
4. 快取檔（`.cgid`）會在 Overwrite 的 `grass` 資料夾裡，用「Move content to Mod…」移到 `grass CS`。檔案要保留在 `grass` 子資料夾中。
5. 看看有沒有 `.fail` 檔。有的話表示那些區域會沒有草，回報 Claude。
6. 重新啟用 `True HUD`。

## 6. xLODGen（地形 LOD）

1. 在「<Edit…>」中選 xLODGen，引數填 `-sse`。
2. 從 MO2 執行，全選世界空間，只勾選 **Terrain LOD**（地形），其餘參數用預設值或照 Claude 的指示。
3. 如果視窗中有輸出（Output）路徑欄位，設為一個空的暫存資料夾，例如 `D:\PM\gen\lodgen`；沒有的話，記下完成時視窗或記錄中顯示的輸出位置。
4. 完成後，把輸出資料夾裡的**全部內容**移到 `D:\PM\mods\lodgen2`。

## 7. TexGen

1. 在「<Edit…>」中選 TexGen，引數填 `-sse`。
2. 從 MO2 執行，用預設設定按「Start」。方案 A 不需要產生草的 billboard。
3. 完成後，把輸出資料夾（預設是 DynDOLOD 資料夾中的 `TexGen_Output`）的全部內容移到 `D:\PM\mods\texgenCS`。
4. 按 `F5` 重新整理，確認 `texgenCS` 已啟用。

## 8. DynDOLOD

1. 在「<Edit…>」中選 DynDOLOD，引數填 `-sse`。
2. 從 MO2 執行，選 **High** 預設（16 GB VRAM 以上）。
3. 方案 A：與草（Grass）相關的 LOD 選項不要勾選。不確定時先截圖給 Claude。
4. 按開始。這會跑好幾個小時。
5. 如果中途停下來並顯示錯誤，把 DynDOLOD 資料夾中 `Logs` 裡最新的記錄檔上傳。
6. 完成後，把輸出資料夾（預設是 DynDOLOD 資料夾中的 `DynDOLOD_Output`）的全部內容移到 `D:\PM\mods\dyndolodCS2`。

## 9. 還原插件順序並檢查

關閉 MO2，執行：

```bat
cd /d C:\PagesTools
python tools\build_instance.py sync-order --pm D:\PM
python tools\build_instance.py sync-order --pm D:\PM --apply
python tools\check_plugins.py --pm D:\PM
python tools\audit_skse.py --pm D:\PM
```

- `sync-order` 第一行是試跑，第二行才寫入。它會把新產生的輸出插件放回目標位置：`DynDOLOD.esm` 在其他 ESM 之後，`DynDOLOD.esp`、`Occlusion.esp` 等放在最後。
- `check_plugins` 這時「待重建的輸出插件」應為 0，而且沒有 `[失敗]`。

## 10. 第一次用 Community Shaders 啟動

1. 從 MO2 用 SKSE 啟動。
2. 左上角出現「Compiling Shaders」時，等它跑完（第一次可能很久）。之後啟動就會很快。
3. 按 `End` 可以開啟 CS 選單。這一階段先用預設值，第 7 階段再調整。

## 11. 新遊戲測試

照 [測試路線](測試路線.md) 開**新遊戲**，走完 30–60 分鐘的固定路線，並記錄結果。

## 12. 凍結為 EN-baseline

測試通過後：

1. 關閉 MO2。
2. 依 [第 8 階段](08-凍結備份與維護.md) 的方法，用 7-Zip 備份：
   - `D:\PM\profiles\Pages-ZH`
   - `D:\PM\ModOrganizer.ini`
   - 8 個輸出資料夾
   - `Pages - 設定覆寫`
3. 壓縮檔命名 `EN-baseline-日期.7z`，放到 D 槽以外的地方。
4. 從此以後，任何修改前都先備份。

## 常見問題

**Overwrite 裡出現其他工具的零碎檔案？**
截圖回報 Claude，不要隨便刪。多數是設定檔，可以移到 `Pages - 設定覆寫`。

**草地快取一直重新開始、停不下來？**
NGIO 說明提到 Root Builder 可能造成這個問題（MO2 plugins 資料夾可能有 M&V 帶來的 Root Builder）。回報 Claude。

**DynDOLOD 說缺少前置或插件有錯誤？**
先執行 `check_plugins.py`，再把兩邊的報告一起上傳。

**遊戲裡有紫色材質或紅色驚嘆號？**
紫色是缺材質檔，紅色驚嘆號是缺模型檔。截圖並記下位置，回報 Claude。
