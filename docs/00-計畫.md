# Skyrim「Pages_Modlist_WIP」下載、組合與繁中化計畫

## Context

### 目標
使用者上傳了一份別人的 WIP 清單，只有 `modlist.txt`（4044 個啟用 mod、95 條分隔線）和 `plugins.txt`（4244 個插件）。目標是：
- 以 **Nolvus Awakening（v6）為基底**，加上 **Mages & Vikings（M&V）** 和其他 mod，組成一份可玩的混合清單。
- **全面翻成台灣繁體中文**。
- 能在使用者的**筆電**上穩定執行。

### 使用者已確認的條件
| 項目 | 內容 |
|---|---|
| 硬體 | 16GB 以上 VRAM 筆電 |
| 空間 | D 槽 1TB |
| 語言 | 繁體中文 |
| 組合原則 | 以 Nolvus 為基底精選，穩定優先 |
| 原作者資料 | 只有兩個 txt，無 meta.ini 或自製檔 |
| 翻譯 | 全面翻譯，接受 LLM／DeepL API 費用 |
| 社群包 | 採用蘇禾簡中漢化包，再轉繁 |
| Patreon／非 Nexus mod | 捨棄，並移除相依修補 |

### 關鍵限制
Claude 在雲端 Linux 容器執行，**無法**操作使用者的 Windows 筆電、Nolvus Dashboard、Wabbajack 或 Nexus 登入。因此分工如下：
- **Claude 交付**：倉庫 `loyuhsi/TEST`（分支 `claude/sharp-faraday-b8ax3h`）裡的分析資料、Windows 用 Python 工具，以及中文操作手冊。
- **使用者執行**：在筆電上照手冊逐步操作，每個階段結束後把工具產生的報告檔回傳（上傳到對話），由 Claude 判讀並決定下一步。

### 研究結論（已交叉查核）
- **Nolvus v6**
  - 最新正式版是 6.0.20（2026-01-27）；6.0.21 仍是 beta。
  - 執行版本是 **1.5.97**：Dashboard 會把 Steam 上的 1.7.104 降版，另建一份 STOCK GAME，並保留 CC 內容。需要 Dashboard 3.8.11 以上。
  - 畫面用 ENB，行為引擎用 Nemesis。
  - Ultimate（不含 SREX）：安裝 426GB，最低 14GB VRAM。
  - Dashboard 語言必須與 Steam 語言相同，而 Dashboard 沒有中文選項。
- **M&V 2.6.2**
  - 從 v2.5 起改為 **1.6.1170**。
  - 安裝 386GB，另需下載 230GB。
  - 只提供 ENB 預設。
  - 規定 Steam 語言必須是英文。
  - 它的 Stock Game 裡的 `Skyrim - Interface.bsa` **內含官方繁中字串與 `fonts_cn.swf`**。
- **目標清單本身**
  - 執行版本：跑在 Nolvus 的 1.5.97 上（SKSE 2.0.20、BEES、Crash Logger 1.5.97、DAV/Skyrim Souls 的 1.5 版）。
  - 內容版本：Nolvus 部分約是 6.0.17，M&V 部分約是 2.5.x。
  - 大改的部分：
    - 用 **Community Shaders**（`Jiaye` 非官方分支，2026-05-28 版）取代 ENB。
    - 用 **Pandora** 取代 Nemesis。
    - 停用約 730 項 Nolvus 的世界與視覺模組，改用 M&V、PBR 和 Lux。
    - Nolvus 的玩法、戰鬥、任務、NPC 和裝備層則保留。
- **插件名額**
  - 4244 個插件，加上 79 個隱含插件（5 個本體 + 74 個 CC），合計 4323。
  - 上限是 254 個完整插件加 4096 個輕量插件，**只剩約 27 個空位**。
  - 所以翻譯**不能新增任何 ESP**，一律改用 DSD 的 JSON 或散檔覆蓋。
- **mod 來源分類**
  - 約 2556 個來自 Nolvus，約 544 個只在 M&V，約 430 個兩邊都有。
  - 約 55 個只存在於舊版 Nolvus；9 個已被 M&V 2.6 移除。
  - 約 431 個是其他公開的 Nexus mod。
  - 13 個不在 Nexus（Patreon 等），依決定捨棄。
  - 9 個是自動產生的輸出，要在本機重建。
  - 3 個是作者自製檔，另有 5 個無法辨識。
- **不可能 1:1 重現的部分**
  - 作者自製的 `CustomFixes1`、`overwrite2`，以及 8 個 `[FIX]*.esp`。
  - 精確的 mod 版本。
  - 所有自動產生的輸出。
  - Nolvus 6.0.17 和 M&V 2.5.x 的原始狀態（Dashboard 與 Wabbajack 只提供最新版）。
- **存檔**：一律要開新遊戲。
- **支援**：這是混合清單，Nolvus 和 M&V 官方都不會提供支援。

## 策略決定

1. **執行版本**：整份清單統一跑在 Nolvus STOCK GAME 的 1.5.97 上。
   - 從 M&V 搬來的 SKSE 外掛，一律換成 1.5.97 版或跨版本（NG）版。
   - 以 M&V 2.40.1（最後一個 1.5.97 版的 `.wabbajack`）和 Nexus 上的檔案資料作為對照表。
2. **畫面**：選官方 Community Shaders 最新版（1.9.1 以上，支援 1.5.97），搭配 Upscaling（DLSS 4）和 FSR Frame Generation。
   - 保留 NAT.CS III、Lux CS 和 PGPatcher。
   - 移除所有 ENB 檔案。
   - 如果官方版和 NAT.CS III 不合，才退回作者用的那份 authored build。
3. **Nolvus 選項**（依目標清單推定）：
   - Ultimate、不含 SREX、Edge UI、16:9、BodySlide Dressed、TAA、True Nord。
   - 附加元件：Fantasy Combat、Boss Encounter、Alternate Leveling、Gore、Exhaustion、Enemies Resistance、Stances Perk Tree。
   - 關閉封存（archiving off）。
   - ENB 隨便選，之後會整個移除。
4. **1TB 空間的安裝順序**：三個資料夾都放在 D 槽同一個 NTFS 分割區，才能用硬連結（hardlink）共用檔案、不重複佔空間。
   - **先裝 M&V**：D:\MV 加下載資料夾，約 616GB。
   - 用硬連結把目標清單要用的約 880 個 M&V 資料夾放進 D:\PM，然後刪掉 M&V 的下載檔和其餘部分。
   - **再裝 Nolvus**（426GB）到 D:\Nolvus，同樣用硬連結放進 D:\PM，然後刪掉目標沒用到的約 730 項。
   - 最後下載其他 mod，並產生輸出檔。
   - 每一步都先檢查剩餘空間，預估峰值超過 900GB 就停下，改用外接 SSD。
5. **組合方式**：另建一個全新的可攜式 MO2 實例 `D:\PM`，Nolvus 和 M&V 的原始實例保持不動。
   - 在第一次開 MO2 **之前**，先替每個目標資料夾建立空的佔位資料夾（不然 MO2 會默默刪掉那些行），並備份兩個 txt。
6. **捨棄項目**：13 個非 Nexus mod、作者自製檔，以及確定無法辨識的 mod。
   - 工具會依插件的前置檔（masters）遞迴停用相依的修補，並產生清單讓使用者確認。
7. **Nolvus 6.0.20 修補缺前置**：如果 6.0.20 的修補插件需要 6.0.19 或 6.0.20 新增的 mod 當前置，就把那些 mod 啟用回來（在名額內優先）。
   - 如果安裝時 6.0.21 已經轉正式版，那 55 個被移除的 mod 改從 Nexus 補下載。
8. **繁中化**：只在英文基準版本穩定之後才疊上去，而且完全不新增插件。

## 階段（每階段都有「退出條件」，並回傳報告）

### Phase 0：Claude 在雲端先做的準備（不需要筆電）
1. 建立倉庫結構，放入目標清單和 Load Order Library 的清單快照。
2. 產生**初版來源分類表**：`data/analysis/provenance.csv`。
3. 從 CDN 分段讀取 M&V 2.6.2 的 `.wabbajack` 清單 JSON（約 30MB），產生「M&V 資料夾 → Nexus 模組 ID／檔案 ID」對照表。
4. 用 Nexus GraphQL 以限速方式比對約 470 個未知 mod：同時比對名稱和插件檔名，產生 `data/analysis/nexus_candidates.csv`。
5. 撰寫全部中文手冊和工具，並寫好單元測試。

### Phase 1：準備筆電（使用者）
- **系統與軟體**
  - Windows 更新。
  - 安裝 VC++、.NET 6 和 .NET 8 Desktop 執行環境、Python 3.12。
  - 分頁檔設為 20–40GB。
  - 在 Windows Defender 把 D:\MV、D:\Nolvus、D:\PM 加入排除清單。
  - 如有 Killer Prioritization Engine，將它停用。
- **Steam 上的 Skyrim**
  - 需要 Skyrim SE 本體加 AE 升級，目前版本 1.7.104。
  - 在遊戲內下載全部 CC 內容。
  - **Steam 語言設為英文**，關閉 Overlay，更新設為「僅在啟動時更新」。
- **帳號**：Nolvus.net、mega.nz、夸克網盤。
- 執行 `tools/preflight.py`：檢查各磁碟剩餘空間、GPU 與 VRAM、RAM、Steam 遊戲版本和 CC 數量。
- **退出條件**：原版遊戲能從 Steam 啟動一次；`preflight` 報告全部通過，並回傳報告。

### Phase 2：安裝 M&V 並擷取需要的部分（使用者 + 工具）
1. 用 Wabbajack 4.2.3 以上，從清單庫安裝 M&V 2.6.2 到 `D:\MV`。
2. 執行 `tools/inventory.py --source mv`：讀出每個 mod 的 `meta.ini` 和 `.wabbajack` 清單，產生 M&V 的清單資料表。
3. 執行 `tools/harvest.py --from mv`：依來源分類表，用硬連結把需要的資料夾放進 `D:\PM\mods`。
4. 從 M&V Stock Game 的 `Skyrim - Interface.bsa` 取出官方繁中字串和字型：用 BSA Browser 或 `tools/zh/extract_official.py`。
5. 確認後刪除 M&V 的下載檔和 `D:\MV`。
- **退出條件**：清單資料表和擷取報告已回傳；D 槽剩餘空間 ≥ 500GB。

### Phase 3：安裝 Nolvus v6（使用者 + 工具）
1. 用 Dashboard 3.8.11 以上安裝 6.0.20 到 `D:\Nolvus`，選項照「策略決定」第 3 點。要盡快裝，避開 6.0.21 轉正式版。
2. 確認安裝結果：
   - 能開到主選單。
   - `STOCK GAME\SkyrimSE.exe` 是 1.5.97.0。
   - `skse64.log` 沒有錯誤。
3. 執行 `inventory.py --source nolvus`，再執行 `harvest.py --from nolvus`。STOCK GAME 也用硬連結複製一份到 `D:\PM`，並移除其中的 `d3d11.dll`、`d3dcompiler_46e.dll`、`d3dcompiler_47.dll` 和 `enb*` 檔案。
4. 刪除目標沒用到的 Nolvus 資料夾。
- **退出條件**：清單資料表已回傳；Nolvus 原本的設定檔已備份成 zip。

### Phase 4：組合（工具為主）
1. 執行 `tools/manifest.py`：以**名稱精確比對**和實際的清單資料表為準，替每個目標資料夾決定動作：
   - 從 Nolvus 用硬連結、從 M&V 用硬連結
   - 從 Nexus 下載（附模組 ID 和檔案 ID）
   - 需換成 1.5.97 版
   - 需重新產生
   - 捨棄
2. 執行 `tools/prune_dependents.py`：處理捨棄項目和它們的相依插件，產生確認清單讓使用者確認。
3. 下載其餘 mod：
   - 預設用 MO2 的「Mod Manager Download」（Premium 可免等待）。
   - 或選用 `tools/nexus_fetch.py`：用使用者自己的 API 金鑰（只從環境變數讀取，絕不寫入檔案），每 3–5 秒下載一個，並帶上 Application-Name 標頭。
4. 執行 `tools/build_instance.py`：
   - 建立可攜式 MO2 和 `ModOrganizer.ini`（遊戲路徑指向 `D:\PM` 的 STOCK GAME）。
   - 建立設定檔 `profiles/Pages-ZH`，寫入 modlist 和 plugins（不寫 loadorder.txt），並加上 `settings.ini`（LocalSettings 和 LocalSaves）。
   - 建立佔位資料夾和分隔線，並備份原檔。
5. 執行 `tools/audit_skse.py`：檢查每個 DLL 是否匯出 `SKSEPlugin_Query`，也就是能否在 1.5.97 上載入。列出需要替換的 DLL，並附上對應的 1.5.97 檔案 ID。
6. 執行 `tools/check_plugins.py`：解析每個插件的 TES4 標頭，檢查：
   - 前置檔是否缺漏
   - 完整插件是否 ≤ 254、輕量插件是否 ≤ 4096
   - form 版本 1.71 的插件是否都有 BEES 支援
- **退出條件**：
  - 不缺前置檔，插件數在上限內。
  - MO2 第一次開啟後，兩個 txt 與備份比對一致。
  - 能開到主選單，`skse64.log` 顯示所有 DLL 都有載入。

### Phase 5：重建輸出並做英文基準測試（使用者，依手冊）
1. 停用 Nolvus 和 M&V 原本的輸出資料夾。
2. 依序產生新的輸出：
   1. Pandora（`-o` 輸出到 Pandora Output）
   2. BodySlide（Dressed）
   3. Synthesis
   4. PGPatcher
   5. NGIO 草地快取（Freak's Floral Fields 設 `iMinGrassSize=60`）
   6. xLODGen 地形
   7. TexGen
   8. DynDOLOD（High，或搭配 CS Grass Optimizations 並把 Grass-Mode 設為 0）
   9. 讓 Community Shaders 建立著色器快取
3. 用 xEdit 執行 Check for Errors，必要時做 QuickAutoClean。
4. **退出條件**：
   - 開新遊戲，走固定測試路線 30–60 分鐘不當機：雪漫城 → 河木鎮森林 → 獨孤城 → 馬卡斯 → FFF 花海。
   - SSE Display Tweaks 的畫面資訊顯示 VRAM 低於預算。
   - 把這個版本凍結並備份成「EN-baseline」。

### Phase 6：繁中化（不新增插件）
1. **本體**
   - 在設定檔的 `Skyrim.ini` 設 `sLanguage=CHINESE`，並保留英文語音。
   - 把官方繁中字串（Phase 2 取出的）做成一個散檔 mod。
   - CC 字串如果缺漏，改用蘇禾的「Skyrim AE & CC」包，再轉成繁體。
2. **字型**
   - 用官方的 `fonts_cn.swf`（先驗證字形涵蓋範圍；不足時改用支援繁體的字型 mod），再寫一份 `fontconfig.txt`，把 Edge UI 和 Sanguis 用到的字型名稱都對應到中文字型，並放在最高優先順序。1.5.97 只會讀 `fontconfig.txt`。
   - ImGui 類 mod 也要設定中文字型：Wheeler、SkyPrompt（需 2.3.13 以上）、Dialogue History、PhotoMode、LamasTinyHUD、SKSE Menu Framework、dMenu。
3. **基礎元件**
   - 新增 Dynamic String Distributor（DSD）1.4.3。
   - 把 Scaleform Translation++ NG 更新到 1.10。
   - 兩者都只有 SKSE 外掛，不佔插件名額。
4. **翻譯疊加順序**
   1. 蘇禾的 Nolvus 6.0.20 Ultimate（不含 SREX）DSD v1.2 加 Other v1.0。
   2. 蘇禾的 M&V 2.5.1 DSD v1.1。它的 Other 包裡的 `.pex`、`.swf`、`.txt`，要用 `tools/zh/diff_pack.py` 比對過、確認與目標 mod 版本相符才採用。
   3. Nexus 上的原生繁中翻譯，例如：Vagrant999 的 Vigilant、Unslaad、Apostasy；sedna1795 的 Bruma；hor0303 的 3DNPC；zeinman55 的 Wyrmstooth 和 SIRENROOT。
   4. 用 SSE Auto Translator 3.2.5 掃描並產生 DSD 輸出。它找不到標為「Traditional Chinese」的翻譯，所以第 3 項要手動匯入。
   - **不使用大學漢化**，因為它要求遊戲語言設在英文。
5. **轉成繁體**：用 `tools/zh/opencc_convert.py`（OpenCC s2twp）處理 DSD 的 JSON、`*_CHINESE.txt`（UTF-16LE 含 BOM）和 MCM 的 JSON。
   - 名詞以官方繁中為準：`tools/zh/strings_glossary.py` 會從官方英文和繁中字串，依字串 ID 對齊，自動產生對照表 `data/zh/glossary.tsv`。
6. **補齊剩餘文字**：
   - 用 `tools/zh/coverage.py` 列出還沒翻譯的字串，並估算字數與 API 費用，**先給使用者確認**。
   - 再用 `tools/zh/llm_translate.py` 翻成台灣繁中：預設用 Claude API，也可切換成 OpenAI 相容端點或 DeepL ZH-HANT；會套用名詞對照表、有快取、每次批次處理多條。
   - 插件文字：用 xTranslator 1.7.x 或 SSE-AT 的 esp2dsd 轉成 DSD 的 JSON。**不修改、不發佈原本的插件**。
7. **MCM 與介面**：
   - 把 `interface/translations/*_ENGLISH.txt` 翻成 `_CHINESE.txt`，並保留一份散檔的 `_ENGLISH.txt` 作為備援。
   - MCM Helper 的 `config.json`、SkyPrompt、Wheeler、QJO、CSF 等 JSON，統一放進「ZH Overrides」這一個 mod。
8. **選做**：`.pex` 腳本裡寫死的顯示字串（用 xTranslator 的 PapyrusPex），以及 Edge UI SWF 裡寫死的標籤（用 JPEXS）。紙地圖的貼圖文字保留英文。
- **退出條件**：
  - 未翻譯字串報告已回傳。
  - 依介面檢查表逐一檢查：主選單、MCM、物品欄、TrueHUD、QuickLoot、Wheeler、書籍、任務日誌、SkyPrompt、主控台，都沒有方框、問號或原始的 `$KEY`。
  - 插件數不變。
  - 除錯時可開 DSD 的 `EnableDebugInfo`，查看哪些字串來自 DSD。

### Phase 7：筆電效能調校（16GB+ 對應 Tier A/S）
- **電源與顯示卡**
  - 插電使用，電源模式設「最佳效能」，並開廠商的 Turbo 模式。
  - MUX 切到獨顯模式。
  - `SkyrimSE.exe` 的 GPU 偏好設為「高效能」，NVIDIA 電源管理設「偏好最高效能」，Windows 縮放 100%。
- **畫面**
  - 解析度 1440p/1600p，開 DLSS Quality 或 Balanced，再加 FSR Frame Generation。
  - 用無邊框視窗，搭配 120Hz 以上螢幕；以 SSE Display Tweaks 限制內部 FPS（例如 60，補幀後 120），也能降溫。
- **材質**：把約 14 個 4K/8K 選項換成 2K；只有超出 VRAM 預算時，才用 VRAMr 的輕度預設。
- **物理模擬**：FSMP 開自動調整，關閉第一人稱 SMP。
- **退出條件**：測試路線維持 50–60 FPS 以上，連續玩 2 小時穩定，溫度可接受。

### Phase 8：凍結、備份與維護
- 絕不在原始實例上按 Nolvus Update，也不執行 Wabbajack 更新。
- STOCK GAME 與 Steam 隔離，Steam 更新不會影響它。
- 備份內容：設定檔、ini、輸出資料夾、翻譯層，以及來源分類表的 CSV。可用 git 或加日期的 7z。
- 選做：編譯一份僅供自己重裝用的私人 `.wabbajack`，**不得散佈**（蘇禾漢化包只限個人使用）。
- **退出條件**：實際測試過一次從備份還原。

實作重點：
- **環境**：只需 Python 3.12 標準庫。只有 `opencc` 和 LLM SDK 是翻譯工具才需要的選用套件。
- **路徑**：一律用 `pathlib`，並處理 Windows 長路徑。
- **安全**：所有會寫入的操作都要加 `--apply` 才會真的執行，並先寫出備份。

資料格式要點：
- `mo2.py`：`modlist.txt` 最上面一行優先權最高；分隔線以 `_separator` 結尾。
- `tes4.py`：讀取 ESM 旗標 0x1、ESL 旗標 0x200、MAST 子記錄和 HEDR 版本。
- `pe.py`：自行解析 PE 的匯出表。
- `wabbajack.py`：`.wabbajack` 是 zip，裡面的 `modlist` 是 JSON，包含 Archives 和 Directives。
- `strings.py`：讀寫 STRINGS、DLSTRINGS、ILSTRINGS 格式。

實作分三個里程碑，依序推進：
- **M1**：資料分析、來源分類表、Nexus 比對、`preflight`、`inventory`，以及 Phase 1–3 手冊。使用者可以立刻開始 Phase 1。
- **M2**：`harvest`、`manifest`、`prune`、`build_instance`、`audit_skse`、`check_plugins`、`nexus_fetch`，以及 Phase 4–5 手冊。
- **M3**：`zh/*` 翻譯工具，以及 Phase 6–8 手冊。
