# 第 4 階段：組合清單（D:\PM）

這一階段把 `D:\PM` 組成可以開到主選單的 MO2 實例：決定每個資料夾的動作、建立 Profile、下載其餘 mod、修剪相依插件、檢查插件與 DLL。

- 預估時間：1–3 天（主要是下載與安裝約 400 多個 mod）。
- 前提：第 2、3 階段完成；`D:\PM` 有 `ModOrganizer.exe` 與 `STOCK GAME`。

> **注意**：會寫入 Profile 的工具（`build_instance.py`、`prune_dependents.py`）執行前**一定要先關閉 MO2**。MO2 關閉時會把它記憶中的清單寫回檔案，蓋掉工具的修改。

## MO2 的基本觀念

- **左側 mod 清單**：越**下面**的 mod 優先權越高（Priority 數字越大），同名檔案會蓋過上面的 mod。
- **資料夾名稱要完全一致**：Profile 依名稱找 mod。安裝時名稱一律照 `manifest.csv` 的「folder」欄，一個字都不能差（包括結尾的數字，例如 `Wyrmstooth2`）。
- **佔位資料夾**：MO2 開啟 Profile 時，會默默刪掉「資料夾不存在」的那幾行。所以 `build_instance.py` 會先替每個目標資料夾建立空的佔位資料夾。之後安裝真正的 mod 時，MO2 會說同名 mod 已存在，這時選 **Replace**。

## 1. 產生組合清單（manifest）

```bat
cd /d C:\PagesTools
python tools\manifest.py --pm D:\PM
```

產生：

- `reports\manifest.csv`：每個目標資料夾一行（可用 Excel 開啟）。
- `reports\downloads.html`：待下載清單（用瀏覽器開啟）。
- `reports\manifest.txt`、`.json`：統計。

`manifest.csv` 的欄位：

| 欄位 | 意思 |
|---|---|
| line | 在目標 `modlist.txt` 的行號 |
| folder | 資料夾名稱（安裝時照抄） |
| section / category | 所在分隔線／來源分類 |
| present | `yes` 表示 `D:\PM\mods` 裡已有內容 |
| action | 要做的事（見下表） |
| nexus_mod_id / nexus_file_id / nexus_version | Nexus 的 mod 編號、檔案編號、版本 |
| id_source | 編號從哪裡查到 |
| url | Nexus 檔案頁連結 |
| ae_only_dlls | 只能在 AE 版執行、1.5.97 無法載入的 DLL |
| note | 備註 |

動作說明：

| action | 意思 | 你要做的事 |
|---|---|---|
| keep | 已就位 | 不用動 |
| download | 需要從 Nexus 下載 | 第 4 節 |
| regenerate | 工具產生的輸出 | 第 5 階段重建，現在不用管 |
| replace_dll | 已就位，但含 AE 專用 DLL | 第 6 節 |
| review | 還找不到來源 | 第 5 節，交給 Claude 判斷 |
| drop | 捨棄（非 Nexus、作者自製等） | 不用動，Profile 會自動排除 |

之後每下載一批，就再跑一次 `manifest.py`，清單會自動更新。

## 2. 建立 D:\PM 實例

1. **先試跑**：
   ```bat
   python tools\build_instance.py create --pm D:\PM ^
     --ini-from "D:\Nolvus\Instances\Nolvus Awakening\MODS\profiles\Nolvus Awakening"
   ```
2. 看結果：遊戲路徑是 `D:\PM\STOCK GAME`、找到的工具、Profile 行數、佔位資料夾數量、遊戲 ini 的來源。
3. 沒有 `[失敗]` 就**實際執行**（同一行加上 `--apply`）：
   ```bat
   python tools\build_instance.py create --pm D:\PM ^
     --ini-from "D:\Nolvus\Instances\Nolvus Awakening\MODS\profiles\Nolvus Awakening" --apply
   ```

這一步會：

- 建立 `D:\PM\ModOrganizer.ini`（可攜式，遊戲指向 `D:\PM\STOCK GAME`）和 `portable.txt`。
- 建立 Profile `Pages-ZH`：寫入目標的 `modlist.txt`、`plugins.txt`（排除捨棄項目），並設定 LocalSaves 與 LocalSettings（存檔和 ini 都放在 Profile 裡）。
- 從 Nolvus 的 Profile 複製 `Skyrim.ini`、`SkyrimPrefs.ini`、`SkyrimCustom.ini`。
- 建立所有佔位資料夾和分隔線。
- 把預期的清單另存在 `D:\PM\profiles\Pages-ZH\_expected`，並把舊檔備份到 `_backup`。

## 3. 第一次開啟 MO2 並驗證

1. 執行 `D:\PM\ModOrganizer.exe`。
   - 詢問是否處理 Nexus 下載連結（nxm）時，選 **Yes**。
   - 詢問是否看教學，選 No。
   - 如果跳出 PageFile Manager，選不要調整。
2. 點上方的設定圖示（Settings）→「Nexus」分頁 →「Connect to Nexus」，在瀏覽器授權。
3. 確認右上角 Profile 是 `Pages-ZH`，左側清單出現大量 mod（多數佔位資料夾是空的，屬正常）。
4. **關閉 MO2**，然後驗證 MO2 沒有刪掉任何行：
   ```bat
   python tools\build_instance.py verify --pm D:\PM
   ```
5. 「modlist.txt 與預期比對」必須是 `[通過]`。如果是 `[失敗]`，停下來回報 Claude。
   - 「plugins.txt 與預期比對」現在會有 `[注意]`，因為很多 mod 還沒安裝，屬正常。

## 4. 下載其餘 mod

### 4.1 用 downloads.html（預設方式）

1. 用瀏覽器開啟 `C:\PagesTools\reports\downloads.html`。
2. 每一列：
   1. 點「Nexus」欄的連結，會開到該 mod 的 Files 分頁並指向正確的檔案。
   2. 按該檔案的 **Mod Manager Download**，讓 MO2 下載（Premium 不用等待）。
   3. 勾選最左邊的方框做記號（只存在這台電腦的瀏覽器）。
3. 被封存（archived）的舊版檔案仍可下載，照樣按 Mod Manager Download。

### 4.2 在 MO2 安裝

1. MO2 右側「Downloads」分頁，對下載好的檔案按兩下。
2. 安裝視窗的 **Name** 欄：清空後，貼上 `downloads.html` 的「資料夾名稱」（點一下就會整段選取，再按 `Ctrl + C`）。
3. 如果出現 **FOMOD 安裝程式**：
   - 選項要讓產生的插件名稱符合 `C:\PagesTools\data\target\plugins.txt`。
   - 用記事本開啟 `plugins.txt`，按 `Ctrl + F` 搜尋這個 mod 的插件名稱，照著選。
   - 不確定時先截圖，選最接近的，之後回報 Claude。
4. MO2 說同名 mod 已存在時，選 **Replace**（取代佔位資料夾）。
5. 確認這個 mod 在左側是勾選（啟用）狀態；右側「Plugins」分頁中，它的插件也要打勾。

### 4.3 （選用）用 nexus_fetch.py 批次下載

適合大量、已有檔案編號的項目。它用你自己的 Nexus 個人 API 金鑰，每個檔案之間等待數秒，並在每小時額度快用完時自動停止。

1. 取得金鑰：登入 Nexus 網站 → 帳號設定（Settings）→ API Keys 頁面 → 最下方的 **Personal API Key**，複製。
2. 在**同一個**命令提示字元視窗中：
   ```bat
   set NEXUS_API_KEY=貼上你的金鑰
   python tools\nexus_fetch.py --pm D:\PM --limit 20
   python tools\nexus_fetch.py --pm D:\PM --limit 20 --apply
   ```
   - 第一行只設定這個視窗；關掉視窗就消失，不會寫進任何檔案。
   - 第二行是試跑，列出會下載哪些；第三行才真的下載。
3. 檔案下載到 `D:\PM\downloads`，並附有 MO2 看得懂的 `.meta` 檔。之後照 4.2 在 MO2 安裝。
4. 報告：`reports\nexus_fetch.txt`、`.json`、`nexus_fetch.csv`。

> **注意**：金鑰等同你的帳號密碼。不要貼到對話、截圖或任何檔案裡。

## 5. review（待確認）項目

1. 上傳 `reports\manifest.csv`。
2. Claude 會逐一判斷，寫進 `data\decisions.csv`（格式 `folder,action,note,nexus_mod_id,nexus_file_id,nexus_version`，後三欄可留空；有填 Nexus 編號時 manifest 會直接列入下載），並告訴你怎麼取得更新後的檔案。
3. 更新後重新執行 `manifest.py`，這些項目會變成 download、drop 等明確動作。

## 6. replace_dll（換成 1.5.97 或 NG 版）

我們的遊戲執行版本是 1.5.97。只支援 AE（1.6.x／1.7.x）的 SKSE 外掛無法載入。

1. 開啟該列的 Nexus 連結，在 Files 分頁找標示 **SE**、**1.5.97**、**Special Edition**、**NG** 或「All versions」的檔案。不要選只寫 AE、1.6.1170 或 1.7 的。
2. 用 Mod Manager Download 下載，安裝到**同一個資料夾名稱**，選 Replace。
3. 如果做過第 2 階段的 2.40.1 對照表，`reports\audit_skse.csv` 的 `hint_1597_mod`、`hint_1597_file` 欄會提示 M&V 當年用的 1.5.97 版檔案。
4. 找不到 1.5.97 版時，回報 Claude（可能改為捨棄）。

## 7. Community Shaders

目標原本用的 CS 是非官方測試版，已經捨棄。改裝官方版：

1. 從 Nexus 安裝下列 mod，名稱照括號中的建議：
   - **Community Shaders**（mod 86492）最新 MAIN 檔（`Community Shaders`）。
   - **Skylighting - Community Shaders**（mod 139352）：NAT.CS III 需要（`CS - Skylighting`）。
   - **Upscaling - Community Shaders**（mod 156952）：DLSS／FSR 與補幀（`CS - Upscaling`）。
   - 建議一併安裝 **Grass Optimizations - Community Shaders**（mod 188628），第 5 階段的草地方案 A 會用到（`CS - Grass Optimizations`）。
2. 把這幾個新 mod 拖到左側清單中 `dyndolodCS2` 的**正下方**（原本 CS 的位置）。
3. 保留清單中原有的 `NAT.CS III` 和 `Lux (cs)`。
4. **不要**安裝 Effects 11（和 NAT.CS III 不相容），也不要放任何 ENB 檔案。
5. 其他 CS 功能外掛只安裝 CS 頁面「Optional Plugins」列出的項目。Claude 看過報告後可能會建議追加。

## 8. 修剪相依插件

捨棄了一些 mod 後，依賴它們的修補插件也要一起停用，否則會缺少前置。

> **注意**：一定要等第 4–6 節都做完（`manifest` 已經沒有 download、review 項目）才執行。工具會把「找不到檔案」的插件當成已捨棄；還沒下載的 mod，它的插件也會被移除。

1. 關閉 MO2，**先試跑**：
   ```bat
   python tools\prune_dependents.py --pm D:\PM
   ```
2. 用 Excel 開啟 `reports\prune-plan.csv`，`action` 為 `remove` 的列會寫原因。把它上傳給 Claude 確認。
3. 確認後**實際執行**：
   ```bat
   python tools\prune_dependents.py --pm D:\PM --disable-folders --apply
   ```
   舊檔會備份到 `D:\PM\profiles\Pages-ZH\_backup\日期時間`。

## 9. 檢查插件與 DLL（重複到沒有 [失敗]）

每裝完一批 mod，關閉 MO2 後依序執行：

```bat
python tools\build_instance.py sync-order --pm D:\PM --apply
python tools\build_instance.py verify --pm D:\PM
python tools\check_plugins.py --pm D:\PM
python tools\audit_skse.py --pm D:\PM --mv-1597-map data\analysis\mv2401_folder_map.csv
```

- `sync-order`：把插件順序還原成目標順序（MO2 會把新找到的插件放在最後）。
- `verify`：列出目標清單中、目前 `plugins.txt` 裡還沒有的插件（尚未安裝、FOMOD 選項不同，或已被修剪）。
- `check_plugins`：檢查缺少前置、前置順序、數量上限、BEES。
  - 「完整插件數」必須 ≤ 254，「輕量插件數」≤ 4096。目標清單加上本體與 CC 後，總共只剩約 **27 個空位**，所以不要自行加入新的插件。
  - 「待重建的輸出插件」（Synthesis.esp、DynDOLOD.esm 等）是 `[資訊]`，第 5 階段才會產生。
- `audit_skse`：檢查每個 DLL 能否在 1.5.97 載入、STOCK GAME 版本、SKSE、Address Library，以及有沒有殘留的 ENB 檔。
  - 沒做 2.40.1 對照表的話，拿掉 `--mv-1597-map ...` 那段。

依報告處理後再跑一次，直到沒有 `[失敗]`。

## 10. 開到主選單

1. 開啟 MO2，右上方執行檔下拉選單選 **SKSE** →「Run」。
2. 第一次啟動時，左上角會出現 Community Shaders 的「Compiling Shaders」，請等它跑完。
3. 進到主選單就算成功，離開遊戲。

## 記錄檔位置

都在 `%USERPROFILE%\Documents\My Games\Skyrim Special Edition\SKSE\`（「文件」被 OneDrive 同步時，在 `OneDrive\文件` 底下）：

| 檔案 | 內容 |
|---|---|
| `skse64.log` | 每個 SKSE 外掛是否載入 |
| `BackportedESLSupport.log` | 哪些插件需要 BEES |
| `crash-日期時間.log` | Crash Logger 的當機報告（當機時才有） |

## 常見問題

**安裝時忘了改名稱，變成另一個資料夾？**
在 MO2 對它按右鍵移除，然後重新從 Downloads 分頁安裝，這次照 manifest 的名稱。

**Nexus 連結顯示找不到或被隱藏？**
可能是成人內容設定或作者隱藏了檔案。截圖回報 Claude。

**`check_plugins` 說「找不到的插件」？**
那個 mod 還沒安裝，或 FOMOD 選項不同。對照 `check_plugins.csv` 的 `problem` 欄處理。

**遊戲一啟動就跳出？**
先看 `skse64.log` 最後幾行和最新的 `crash-*.log`，一起上傳。
